# Deploying OushodhSathi

Two pieces: the FastAPI backend on **Render** and the Next.js frontend on **Vercel**.
Both deploy from this GitHub repository. No secret is ever committed; every key is
entered in the provider's dashboard.

## 1. Backend → Render

1. Render dashboard → **New → Blueprint** → choose this repository. Render reads
   [`render.yaml`](../render.yaml) and proposes one web service, `oushodhsathi-api`.
2. Fill in the variables marked *sync: false* when Render asks for them:

   | Name | Required | What to put |
   | --- | --- | --- |
   | `CORS_ORIGINS` | yes | Your Vercel URL, e.g. `https://oushodhsathi.vercel.app` |
   | `CORS_ORIGIN_REGEX` | no | `^https://oushodhsathi-.*\.vercel\.app$` to allow preview deploys |
   | `OPENROUTER_API_KEY` | for live scans | Your OpenRouter key |
   | `OPENROUTER_VISION_MODEL`, `OPENROUTER_TEXT_MODEL` | no | Blank = auto-pick a free model |
   | `TAVILY_API_KEY`, `PERPLEXITY_API_KEY` | no | Unknown-brand web lookup |
   | `N8N_ALERT_WEBHOOK` | no | n8n webhook for red-flag doctor alerts |

   `REVIEWER_TOKEN` is generated by Render. Open the service → **Environment** to read
   it; that is the token reviewers type on `/review`.
3. Deploy. SQLite lives on the 1 GB persistent disk at `/var/data/oushodh.db`, so data
   survives restarts. The pre-deploy step seeds the invented demo household once
   (`scripts/seed_demo.py --if-empty`) and never overwrites real data.
4. Check `https://<service>.onrender.com/health` returns `"status": "ok"`.

Ollama does not run on Render (`OLLAMA_DISABLED=1`), so hosted Bangla explanations use
the cloud fallback, then the fixed templates. Run locally for private explanations.

`DEMO_MODE=true` lets the scan flow work without any keys (it returns the demo shelf).
Set it to `false` once a vision key is configured.

## 2. Frontend → Vercel

1. Vercel → **Add New → Project** → import this repository.
2. **Root Directory**: `frontend`. Framework preset: Next.js (auto-detected).
3. Environment variable: `NEXT_PUBLIC_API_URL` = `https://<service>.onrender.com`.
4. Deploy, then put the Vercel URL into Render's `CORS_ORIGINS` and redeploy the API.

## 3. Smoke test

- `/` landing → **See the demo** → step through `/demo`.
- `/review` → sign in with the Render `REVIEWER_TOKEN` → confirm a flag with a note.
- `/p/1/results` now shows the confirmed flag with its Bangla explanation.
- `/passport/1` → browser print preview (A5).

## 4. Secrets hygiene

Before every release, search the history for key prefixes:

```
git log --all -p | grep -nE "sk-[A-Za-z0-9_-]{10,}|pplx-|tvly-[A-Za-z0-9]|xpl_"
```

Last checked on the `prototype` branch: no real keys found (one fake test value,
`tvly-secret-value`, in `backend/tests`). Keys pasted into any chat must be rotated
regardless.
