# Deploying OushodhSathi

Two pieces: the FastAPI backend on **Render** and the Next.js frontend on **Vercel**.
Both deploy from this GitHub repository. No secret is ever committed; every key is
entered in the provider's dashboard.

## 1. Backend → Render

1. Open **<https://dashboard.render.com/blueprint/new?repo=https://github.com/ProttoyDip/OushodhSathi->**
   (Render dashboard → **New → Blueprint** → this repository), pick the branch to deploy, and
   apply. Render reads [`render.yaml`](../render.yaml) and creates one Free web service,
   `oushodhsathi-api`, in Singapore.
2. Render asks for the variables marked *sync: false*. All are optional; leave them blank to run
   in demo mode:

   | Name | What to put |
   | --- | --- |
   | `OPENROUTER_API_KEY` | Your OpenRouter key, for reading real photos |
   | `TAVILY_API_KEY`, `PERPLEXITY_API_KEY` | Unknown-brand web lookup |
   | `N8N_ALERT_WEBHOOK` | n8n webhook for red-flag doctor alerts |

   `REVIEWER_TOKEN` is **generated by Render** and never written anywhere else. Open the service →
   **Environment** to read it; that is the token reviewers type on `/review`.
   `CORS_ORIGIN_REGEX` already allows `https://oushodhsathi*.vercel.app`; if your Vercel URL is
   different, add it as `CORS_ORIGINS`.
3. Deploy. On the Free plan there is no persistent disk: SQLite lives on the instance and the
   start command seeds the invented demo household (`scripts/seed_demo.py --if-empty`). Reviews
   are lost on restart or spin-down, and the service sleeps after 15 minutes idle (the first
   request then takes about a minute). For persistence, see the comment at the top of
   `render.yaml`.
4. Check `https://<service>.onrender.com/health` returns `"status": "ok"`.

Ollama does not run on Render (`OLLAMA_DISABLED=1`), so hosted Bangla explanations use the cloud
fallback, then the fixed templates. Run locally for private explanations.

`DEMO_MODE=true` lets the scan flow work without any keys (it returns the demo shelf).
Set it to `false` once a vision key is configured.

## 2. Frontend → Vercel

1. Vercel → **Add New → Project** → import this repository.
2. **Root Directory**: `frontend`. Framework preset: Next.js (auto-detected).
3. Environment variable: `NEXT_PUBLIC_API_URL` = `https://<service>.onrender.com`.
4. Deploy. If the Vercel URL does not start with `https://oushodhsathi`, add it to Render's
   `CORS_ORIGINS` and redeploy the API.

## 3. Smoke test

- `/` landing → **See the demo** → step through `/demo`.
- `/review` → sign in with the Render `REVIEWER_TOKEN` → confirm a flag with a note.
- `/p/1/results` now shows the confirmed flag with its Bangla explanation.
- `/passport/1` → browser print preview (A5).

## 4. Secrets hygiene

Before every release, search the history for key prefixes:

```
git log --all -p | grep -nE "sk-[A-Za-z0-9_-]{10,}|pplx-|tvly-[A-Za-z0-9]|xpl_"
```

Last checked on the `prototype` branch: no real keys found (one fake test value,
`tvly-secret-value`, in `backend/tests`). Keys pasted into any chat must be rotated
regardless.
